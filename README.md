1. `double` хранит числа в двоичном формате и не может точно представить некоторые десятичные дроби. Если мы напишем в double '0,1 + 0,2', то он выведет там не ровно '0,3', а `0.30000000000000004`. Для денег это недопустимо, потому что копейки могут поплыть. `decimal` хранит числа в десятичном формате с  точностью, поэтому `0.1m + 0.2m` даёт ровно `0.3`. Для финансовых расчётов всегда используется decimal (с суффиксом `m`).
2. Значение «обернётся» по кругу. Например, `byte` хранит от 0 до 255, и `255 + 1` даст `0`, а не 256. Это называется переполнение (overflow). В C# по умолчанию переполнение не вызывает ошибку, значение просто берётся по модулю диапазона.
3. `var` — это не динамическая типизация. Тип переменной определяется один раз во время компиляции, по правой части выражения. После этого переменная имеет строго фиксированный тип, и присвоить ей значение другого типа нельзя, а вот например в Python где `x = 5`, потом `x = "текст"` это нормально. `var age = 20;` — это ровно то же, что `int age = 20;`, просто тип не написан явно.
4. Всегда `string`. Даже если пользователь ввёл `123`, то это будет строка `"123"`, а не число. Чтобы получить число, строку нужно преобразовать через `Convert.ToInt32`, `int.Parse` или `int.TryParse`.
5. `int.Parse("abc")`  бросит исключение `FormatException`, программа упадёт с ошибкой.
`int.TryParse("abc", out int result)`не упадет, а вернёт `false`, а в переменную `result` запишет `0`.
TryParse безопаснее, потому что не роняет программу из-за плохого ввода.
6. `false` означает, что строку не удалось преобразовать в число. Например, пользователь ввёл буквы. В переменную через `out` в этом случае попадёт значение по умолчанию для типа, для `int` это `0`.
7.Всегда, когда ввод идёт от пользователя, а это почти всегда. Пользователь может ввести что угодно: буквы, пробелы, знаки. Если использовать `Parse`, программа упадёт с `FormatException`. С `TryParse` программа продолжит работу, а мы сможем обработать ошибку (напишем `if (ok) { ... } else { ... }`). Пример: ввод возраста, года рождения, количества книг — везде лучше `TryParse`.
